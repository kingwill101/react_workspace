# CLI reference

`react_tool` owns project scaffolding, Dart generation, JavaScript dependency
management, browser and SSR compilation, and local process orchestration.

Run it from an application package:

```console
dart run react_tool:react <command>
```

After global activation, the shorter `react <command>` form is equivalent:

```console
dart pub global activate react_tool
react doctor
```

## Command overview

| Command | Purpose |
| --- | --- |
| `doctor` | Inspect resolved project configuration and development readiness. |
| `init` | Scaffold an SSR, client-only, or Routed application. |
| `generate` | Generate Dart sources into `lib/.generated/` without compiling bundles. |
| `build` | Generate sources and compile production artifacts. |
| `prerender` | Render selected SSR routes into static HTML files. |
| `serve` | Build, then run the application server and optional Node SSR worker. |
| `clean` | Remove React-owned build and generated outputs. |
| `js install` | Provision the managed npm environment. |
| `js sync` | Validate npm requirements in host-JS mode. |
| `component list` | Enumerate public React component exports in a local TSX module. |
| `component add` | Declare, infer, generate, and validate a local or npm component wrapper. |
| `shadcn add` | Apply shadcn naming and directory conventions to `component add`. |
| `ts bind` | Generate typed Dart bindings and registration shims from TypeScript. |
| `analyze` | Run Dart analysis and print resolved React usage information. |
| `test` | Run Dart tests, optionally with coverage. |

## `react doctor`

```console
dart run react_tool:react doctor
```

Reports the package root, configuration source, client/SSR/server entrypoints,
styles, static directory, output directory, and whether analysis and testing
support are configured. Run it from a directory containing `pubspec.yaml`.

## `react init`

```console
dart run react_tool:react init <project_name> [options]
```

Options:

- `--template <ssr|client|routed|routed-minimal>` selects the starter. The
  default is `ssr`.
- `--packages <path>` selects the local React package directory used by the
  generated path dependencies. It defaults to `../packages`.
- `--force` allows writing into an existing target directory.

The `routed` templates use `react_server_routed` and `routed_io` without a
Shelf dependency. `routed-minimal` keeps the same full-stack behavior while
reducing starter-facing files.

```console
dart run react_tool:react init dashboard --template routed-minimal
cd dashboard
dart pub get
dart run react_tool:react serve
```

## `react generate`

```console
dart run react_tool:react generate
```

Runs build-runner generation and synchronizes application-facing outputs into
`lib/.generated/`. It does not compile CSS, browser JavaScript, or the SSR
worker. Use it when changing component signatures, server functions, or
generated imports and you want a quick feedback cycle.

Import generated factories through package URIs:

```dart
import 'package:my_app/.generated/app.react.dart';
```

Do not edit or commit `lib/.generated/`; change the annotated source,
generator, or scaffold template and regenerate.

For a multi-package workspace, CI can compile all builders once and then sync
each application's package-local imports without repeating the build:

```console
dart run build_runner build --workspace
cd examples/my_app
dart run react_tool:react generate --sync-only
```

`--sync-only` never invokes build-runner. It expects a successful workspace
build to already exist under the nearest `.dart_tool/build/generated/` tree,
so it is an orchestration option rather than the normal development command.

## `react build`

```console
dart run react_tool:react build [--release] [--server] [--watch]
```

- `--release` uses release optimization for the client bundle.
- `--server` also compiles the configured Dart server to a native executable.
- `--watch` rebuilds when authored project files change.

A full build can produce:

- `build/react/browser.entry.mjs` and the compiled Dart client;
- `build/react/ssr.entry.mjs`, `ssr_runtime.mjs`, and the compiled SSR code;
- compiled styles and copied static assets;
- browser and SSR foreign-module bundles;
- `bundle_manifest.json` and `bundle_report.json`;
- an optional native server executable.

## `react prerender`

```console
dart run react_tool:react prerender \
  --routes /,/about,/docs/getting-started \
  --output build/prerendered
```

For a checked-in route list, use a JSON manifest instead:

```console
dart run react_tool:react prerender \
  --manifest config/prerender.json \
  --output build/prerendered
```

The manifest can be either an array such as `["/", "/about"]` or an object
such as `{ "routes": ["/", "/about"] }`.

`prerender` builds the project, starts the configured server and generated SSR
worker, requests each route, and writes the returned HTML. `/` becomes
`index.html`; extensionless routes become nested `index.html` files such as
`about/index.html`. Routes cannot contain query strings, fragments, or parent
directory traversal. This is explicit static generation and does not provide
persistent ISR or stale-while-revalidate behavior.

## `react serve`

```console
dart run react_tool:react serve \
  [--port 8080] [--ssr-port 3001] \
  [--watch] [--release] [--no-ssr]
```

`serve` builds first, then starts the configured Dart server. If an SSR bundle
exists, it also starts the generated Node worker and passes its URL to the
server. Client-only projects use the built-in static server.

- `--port` selects the application port.
- `--ssr-port` selects the worker port.
- `--no-ssr` starts only the Dart application server.
- `--watch` rebuilds and restarts after successful changes.
- `--release` builds optimized client output.

For tests, use `ReactTestHarness` rather than fixed ports; it allocates isolated
ports and composes with the selected `server_testing` adapter.

## `react clean`

```console
dart run react_tool:react clean
```

Removes `build/react/`, `lib/.generated/`, generated CSS-module bindings,
and legacy project-level foreign-component bindings owned by the tool. It does
not remove authored source or the complete Dart build cache.

## JavaScript environment

```console
dart run react_tool:react js install
dart run react_tool:react js sync
```

`js install` resolves wrapper descriptors and provisions exact npm versions
under `.dart_tool/react/js/`. It does not mutate the application's
`package.json`.

`js sync` is for `foreign.host: true` projects. It validates that the host
JavaScript project satisfies every wrapper dependency and peer range.

## TypeScript bindings

### Foreign component workflow

For local React components, enumerate exports first:

```console
dart run react_tool:react component list web/components/ui/field.tsx
```

Then declare the exports you want to use:

```console
dart run react_tool:react component add shadcn.Field \
  web/components/ui/field.tsx --export Field --infer
```

Use `--no-validate` while adding several exports, then run one full build. Add
explicit `name:type` arguments when TypeScript utility types such as
`React.ComponentProps<"textarea">` are intentionally broad:

```console
dart run react_tool:react component add shadcn.Textarea \
  web/components/ui/textarea.tsx \
  'className:String?' 'placeholder:String?' 'rows:num?' \
  --export Textarea --infer --no-validate
```

The generated wrappers are retained only when authored Dart code references
them. This keeps the browser and SSR foreign bundles small.

Explicit mode extracts selected exports, or discovers components and hooks when
no names are supplied:

```console
dart run react_tool:react ts bind react-router-dom MemoryRouter Link \
  --output lib/src/router_bindings.g.dart \
  --shim lib/src/router_shim.mjs \
  --hooks lib/src/router_hooks.g.dart \
  --namespace reactRouter \
  --prefix reactRouter
```

Options:

- `--output`, `-o`: Dart binding output.
- `--shim`: self-registering JavaScript module.
- `--hooks`: Dart hook binding output.
- `--namespace`: isolated global hook/function bridge namespace.
- `--prefix`: component registration-key prefix.
- `--type-prefix`: prefix generated Dart type names to avoid collisions.
- `--npm-root`: resolve declarations from a nonstandard npm installation.

Declarative mode regenerates every `react.js.bind` group in `react.yaml` or
`pubspec.yaml`:

```yaml
react:
  js:
    bind:
      - specifier: some-react-library
        output: lib/src/some_bindings.g.dart
        shim: lib/src/some_bindings_shim.mjs
        hooks: lib/src/some_hooks.g.dart
        namespace: someLibrary
        prefix: someLibrary
        exclude: [UnsupportedExport]
```

```console
dart run react_tool:react js install
dart run react_tool:react ts bind
```

Generated wrapper files are normally committed and reviewed because they are
the wrapper package's implementation. Application codegen under
`lib/.generated/` is ephemeral.

## Analysis and tests

```console
dart run react_tool:react analyze [--path <project>] [--verbose]
dart run react_tool:react test [--path <test-path>] [--coverage]
```

`analyze` runs `dart analyze`; when the analyzer plugin is enabled, its React
rules participate. It also previews resolved component and hook usage for the
configured client and SSR entrypoints.

`test` delegates to `dart test`. The default path is `test`; `--coverage`
writes `coverage/lcov.info`. Use `react_testing` and the relevant
`server_testing` adapter for component, SSR, asset, and server-function
behavior.
