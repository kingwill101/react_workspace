# CLI Reference (`react_tool`)

The `react_tool` package exposes the `react` executable, which orchestrates the entire build and development lifecycle of a React Dart application.

## Global Activation

```bash
dart pub global activate react_tool
```

You can then run `react <command>` or `dart run react_tool:react <command>`.

## Commands

### `react doctor`
Inspects the current project and verifies that the `react.yaml` configuration is valid, dependencies are installed, and the environment is ready for development.

### `react init <directory> [--template <name>]`
Scaffolds a new React Dart project.
- `--template ssr` (default): Creates a full-stack SSR project with a backend server.
- `--template client`: Creates a client-only static site project.

### `react build`
Compiles the application for production.
- **Flags**:
  - `--release`: Minifies Dart and JS outputs, and compresses CSS.
  - `--watch`: Watches the file system and incrementally rebuilds on changes.
- **Outputs**: Generates files into the configured output directory (usually `build/react/`). This includes the manifest, JS bundles, and compiled stylesheets.

### `react serve`
Starts the development server.
- **Flags**:
  - `--watch`: Rebuilds and restarts the server on code changes.
  - `--release`: Runs the server using release-mode artifacts.
  - `--no-ssr`: Disables the SSR worker for debugging client-side rendering.
- **Behavior**: Runs the Dart executable specified in `serverEntrypoint` (e.g., `bin/server.dart`). In client-only mode, it spins up a simple static file server instead.

### `react js install`
Provisions an isolated NPM environment in `.dart_tool/react/js`. This is used internally during `build`, but can be run manually to force an npm dependency resolution based on your wrapper definitions.

### `react js sync`
Validates that a host JS project satisfies all wrapper requirements. Useful when `foreign.host: true` is set in `react.yaml`.

### `react ts bind <specifier> [names...]`
Extracts TypeScript declarations from an NPM package and generates Dart bindings.
- **Arguments**:
  - `<specifier>`: The npm package name (e.g., `react-router-dom`).
  - `[names...]`: Specific exports to bind. If omitted, discovers all React components and hooks.
- **Flags**:
  - `--hooks <file>`: Specify an output file for generated hook bindings.
