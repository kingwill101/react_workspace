# API overview

This is a package map, not a replacement for generated Dartdoc.

## `react`

Portable UI and runtime contracts:

- `ReactNode`, `Component`, `HostNode`, `ForeignComponent`, `Text`,
  `Fragment`, and `Empty`;
- `ReactChildren` and `normalizeChildren`;
- `@reactComponent` / `ReactComponent`;
- state, effect, memo, callback, ref, context, transition, external-store, and
  React 18/19 hooks;
- context providers, suspense, lazy, memo, forward-ref, portals, strict mode,
  error boundaries, and runtime capability contracts.

## `react_dom`

Recommended web component entrypoint. Re-exports `react` and `react_web`,
then adds:

- `initReact()`;
- `getRoot(id)` and `getInitialProps()`;
- `hasSSRContent(root)`;
- `mount(root, node)` and `hydrate(root, node)`.

## `react_web`

Generated HTML/SVG factories, typed React synthetic events, portable Web API
interfaces, SSR metadata, browser adapters, `css`, `classNames`,
`dataAttributes`, `aria`, and the browser
`HttpServerFunctionClient`.

The mirrored Web surface is pinned to `package:web 1.1.1`.

## `react_actions`

- `@serverFunction` and `@serverData`;
- `ServerFunctionId`, `ServerFunctionRef`, and JSON codec contracts;
- `ServerFunctionClient` and `runWithServerFunctionClient`;
- versioned request/response envelopes and structured failures.

## `react_server`

- `ServerFunctionContext`, `CancellationToken`, and
  `ServerFunctionRegistry`;
- `ReactSsrClient` and `ReactSsrDocument` on the Dart VM;
- `registerGlobalRenderer` and `renderToString` in the compiled Node SSR
  entrypoint.

HTTP integration is intentionally absent.

## Server adapters

- `react_server_routed`: `RoutedReactApplication`,
  `RoutedReactPageProps`, and `RoutedReactAuthentication`;
- `react_server_shelf`: `ReactServerApp`, `ReactPageProps`, and
  `createServerActionHandler`.

## `react_testing`

- `ReactComponentHarness`: portable trees, hooks, refs, contexts, and runtime
  capabilities;
- `ServerFunctionHarness`: direct dispatch and HTTP envelope assertions;
- `SsrTestHarness` / `InMemorySsrHarness`: worker and document behavior;
- `ReactTestHarness`: actual builds, generated assets, and Node SSR worker;
- `GeneratorFidelityHarness`: generated Web surface completeness.

The package depends on the `server_testing` base; applications choose the
concrete server adapter.

## Tooling

- `react_codegen`: Dart component/action builders;
- `react_tool`: scaffold, generate, build, serve, npm, TypeScript bindings,
  analysis, and tests;
- `react_analysis`: shared component/hook/SSR/import semantics;
- `react_analyzer`: analysis-server diagnostics, fixes, and assists.
