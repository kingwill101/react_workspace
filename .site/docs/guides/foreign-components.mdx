# Foreign JavaScript and TypeScript components

React Dart can render npm components and custom JS/TS modules through the same
browser and SSR bundle graph. Use project configuration for app-local modules;
create a wrapper package for reusable libraries.

## Project-local component

Declare the module and exported prop contract:

```yaml
foreign:
  components:
    - name: DatePicker
      module: web/components/date_picker.js
      export: default
      props:
        value: String
        onChange: ReactCallback
```

A build writes the typed helper to
`lib/.generated/foreign_components.g.dart` and bundles the JavaScript module
for browser and SSR targets.

```dart
import 'package:my_app/.generated/foreign_components.g.dart';
import 'package:react_dom/react_dom.dart';

@reactComponent
ReactNode Form(({String value}) props) {
  return datePicker(
    value: props.value,
    onChange: ReactCallback.one((next) {
      print('Changed to $next');
    }),
  );
}
```

Ordinary supported Dart callbacks are encoded by the runtime. Do not import
legacy `dart:js_util` or call `allowInterop` in component source.

For exploratory or dynamic APIs, use the generic bridge:

```dart
foreignComponent(
  'charts.LineChart',
  props: {
    'data': data,
    'animated': true,
    'onSelect': ReactCallback.one<Object?>((value) => select(value)),
  },
)
```

The key must match the name registered by the module or generated shim.

## Generate TypeScript bindings

Provision the package's declared npm dependencies, then extract declarations:

```console
dart run react_tool:react js install
dart run react_tool:react ts bind some-react-library \
  --output lib/src/some_bindings.g.dart \
  --shim lib/src/some_bindings_shim.mjs \
  --hooks lib/src/some_hooks.g.dart \
  --namespace someLibrary \
  --prefix someLibrary
```

The extractor maps component props, literal unions, interfaces, nested
callbacks, hook parameters, and hook return values into typed Dart APIs. The
shim imports only referenced exports and registers components plus an isolated
hook/function bridge.

Generated component bindings expose both direct calls and typed props builders:

```dart
final textarea = textareaProps()
  ..id = 'feedback'
  ..placeholder = 'Tell us what you think'
  ..rows = 4;

return textarea();
```

The builder form is generated for project-local foreign declarations and for
`react ts bind` output. It produces the same `ForeignComponent` node as the
direct helper, so it remains compatible with browser rendering, SSR, and
`react_testing`.

For deterministic wrapper maintenance, put the same options in a
`react.js.bind` group and run `react ts bind` with no arguments. Commit and
review wrapper outputs; application `lib/.generated/` output remains ignored.

## Wrapper package contract

A reusable package owns:

- a public Dart entrypoint;
- generated or handwritten Dart bindings;
- a JavaScript registration shim;
- `react.js` npm dependencies, peers, externals, and target entries;
- native harness tests and browser/SSR bundle tests.

Keep `react` and `react-dom` as peers/externals so every wrapper shares one
runtime instance. See [Build a Dart wrapper for a JavaScript
package](./wrapper-packages) for the complete descriptor and the handwritten
Zustand escape hatch.
