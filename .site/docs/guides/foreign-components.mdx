# Foreign Components (JS/TS)

While React Dart allows you to write components in Dart, the React ecosystem is vast and built on JavaScript. React Dart makes it trivial to consume existing NPM packages, complex UI libraries (like Material UI or Radix), and custom JS/TS components without writing tedious `dart:js_interop` code.

## Registering a Foreign Component

To use a JavaScript or TypeScript component, you register it in your `react.yaml` under the `foreign.components` configuration.

```yaml
# react.yaml
foreign:
  components:
    - name: DatePicker
      module: web/components/date_picker.js
      export: default
      props:
        value: String
        onChange: Function
```

### Configuration Details

- **`name`**: The Dart name you will use to reference this component.
- **`module`**: The path to the JS/TS file or the NPM package specifier.
- **`export`**: The export name (e.g., `default` or a named export like `DatePicker`).
- **`props`**: (Optional) A map of property names to Dart types. If provided, the code generator creates a typed helper in `lib/foreign_components.g.dart`.

## Usage in Dart

Once registered, the build system uses esbuild to bundle the JS file into `foreign/browser/bundle.mjs` and `foreign/ssr/bundle.mjs`.

In your Dart code, you can use the generic `foreignComponent` function from `package:react/react.dart`:

```dart
import 'package:react/react.dart';

@React()
ReactNode Form() {
  return div(children: [
    foreignComponent(
      'DatePicker',
      props: {
        'value': '2024-01-01',
        'onChange': allowInterop((e) => print(e)),
      },
    )
  ]);
}
```

## Generated Typed Wrappers

If you defined `props` in `react.yaml`, the `react_codegen` builder generates a strongly typed wrapper function.

```dart
// Import the generated wrappers
import 'package:my_app/foreign_components.g.dart';

@React()
ReactNode Form() {
  return div(children: [
    // Use the strongly typed wrapper
    datePicker(
      value: '2024-01-01',
      onChange: allowInterop((e) => print('Changed: $e')),
    )
  ]);
}
```

## Consuming NPM Packages

You can use the exact same mechanism to wrap NPM packages.

```yaml
# react.yaml
foreign:
  components:
    - name: LineChart
      module: recharts
      export: LineChart
```

For complex libraries, the community convention is to create a "wrapper package" (e.g., `react_router` or `react_recharts`). The wrapper package uses a JS shim to register the components globally, and provides Dart wrappers. See the **Wrapping third-party React packages** section in the main README for advanced wrapper patterns using `react.js` definitions in `pubspec.yaml`.

## TypeScript Declarations Integration

Instead of manually typing out `props` in `react.yaml`, React Dart CLI can automatically generate bindings from TypeScript declarations using `react ts bind`.

```bash
dart run react_tool:react ts bind react-router-dom
```

This extracts the API surface from the NPM package and generates type-safe Dart wrappers automatically, saving you immense boilerplate. You define binding rules in `react.yaml` under `js.bind`.
