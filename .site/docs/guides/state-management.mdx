# State Management

Managing state in React Dart applications feels very similar to traditional React or Flutter, but leverages Dart's powerful ecosystem. Depending on the complexity of your application, you can use local hooks, Context, or integrate with popular Dart state management libraries.

## 1. Local State with Hooks

For component-level state, use the `useState` hook provided by `package:react`.

```dart
import 'package:react/react.dart';
import 'counter.react.dart';

@React()
ReactNode Counter() {
  final (count, setCount) = useState(0);

  return div(children: [
    h1(children: [Text('Count: $count')]),
    button(
      onClick: (e) => setCount(count + 1),
      children: [Text('Increment')],
    )
  ]);
}
```

State created with `useState` is strictly bound to the component instance.

## 2. Global State via Prop Drilling

For small applications, passing state down as props from a root component is often sufficient. Because Dart has a succinct syntax, prop drilling is less verbose than in some other languages.

## 3. Integrating Dart State Libraries

Because React Dart runs Dart code, you can use existing Dart state management patterns. The challenge is ensuring the React tree re-renders when the state changes.

### Signals (e.g., `signals_dart`)

Signals are highly compatible with React's functional model. You can create a custom hook to subscribe to a signal and trigger a re-render.

```dart
import 'package:react/react.dart';
import 'package:signals_dart/signals_dart.dart';

// Create a global signal
final counterSignal = signal(0);

// A custom hook to bind a signal to React state
T useSignal<T>(Signal<T> s) {
  final (val, setVal) = useState(s.value);
  
  useEffect(() {
    final cleanup = s.subscribe((newValue) => setVal(newValue));
    return cleanup;
  }, [s]);
  
  return val;
}

@React()
ReactNode SignalCounter() {
  final count = useSignal(counterSignal);
  
  return button(
    onClick: (_) => counterSignal.value++,
    children: [Text('Signal Count: $count')],
  );
}
```

### BLoC / Riverpod

While you *can* use complex libraries like `bloc` or `riverpod`, it often requires writing adapter hooks similar to the `useSignal` example above to bridge the stream/provider emission into a `useState` update.

For example, with a Stream:

```dart
T? useStream<T>(Stream<T> stream, {T? initialValue}) {
  final (data, setData) = useState<T?>(initialValue);
  
  useEffect(() {
    final sub = stream.listen(setData);
    return sub.cancel;
  }, [stream]);
  
  return data;
}
```

## Server State vs Client State

When using Server Functions (`@serverFunction`), remember that the server is stateless between requests.

- **Client State**: UI toggles, form inputs, local caches. Managed via `useState`.
- **Server State**: Database records, session data. Fetched via Server Functions and stored locally in client state while the user interacts with it.

If you need robust server-state caching (similar to React Query or SWR), you can build a custom hook that wraps your Server Function calls, handles `isLoading`/`error` states, and deduplicates requests.
