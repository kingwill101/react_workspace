# State management

Use local hooks for component state and `useSyncExternalStore`-based adapters
for external Dart stores. The same portable APIs can render in the browser,
Node SSR worker, and native component harness.

## Local state

```dart
import 'package:react_dom/react_dom.dart';

@reactComponent
ReactNode Counter(({int initial}) props) {
  final (count, setCount) = useState(props.initial);

  return button(
    type: 'button',
    onClick: (_) => setCount(count + 1),
    children: ['Count: $count'],
  );
}
```

State belongs to the generated component identity and key. Keep hooks at the
top level and use stable keys when rendering component lists.

## Derived and deferred values

Use `useMemo` for expensive derived values, `useDeferredValue` for
lower-priority rendering, and `useTransition` when a state update may render a
large subtree.

```dart
final filtered = useMemo(
  () => items.where((item) => item.matches(query)).toList(),
  [items, query],
);
final deferredItems = useDeferredValue(filtered);
```

## Custom hooks

A custom hook is an ordinary Dart function that calls hook primitives and
returns a typed value. For example, a translation hook can own the selected
language and expose direction plus translated strings:

```dart
({String dir, TranslationValues t, void Function(String) setLanguage})
useTranslation(
  Translations translations, {
  required String initialLanguage,
}) {
  final (language, setLanguage) = useState(initialLanguage);
  final selected = translations[language]!;
  return (dir: selected.dir, t: selected.values, setLanguage: setLanguage);
}
```

Custom hooks follow the same rules as React hooks: call them only from a
component or another hook, never conditionally, and keep the initial state
stable for SSR hydration. See [Define a custom Dart hook](../tutorials/custom-dart-hooks)
for a complete implementation.

## External Dart stores

`useSyncExternalStore` is the primitive for subscriptions outside React:

```dart
final value = useSyncExternalStore<int>(
  store.subscribe,
  store.snapshot,
  store.snapshot,
);
```

The third callback supplies an SSR snapshot. It must be deterministic relative
to the initial browser snapshot to avoid hydration mismatches.

The workspace provides typed adapters:

- `react_bloc`: `BlocProvider`, `useBloc`, `useBlocState`, and
  `useBlocSelector`;
- `react_riverpod`: provider-container context and provider subscription
  hooks;
- `react_zustand`: a small npm-backed Zustand wrapper and reference for
  handwritten JavaScript package bridges.

## Context

Use `createContext`, providers, and `useContext` for values scoped to a
subtree. Context is appropriate for dependencies and configuration; use an
external store when updates are frequent or selectors should isolate rebuilds.

## Server state

A server function performs authenticated I/O on the Dart server. Its generated
client proxy returns a `Future`; store the result in local or external state
and model loading/error transitions explicitly.

Server memory is not browser state. Do not rely on module-level server
variables for durable multi-instance persistence.
