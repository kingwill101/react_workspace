# Styling

React Dart supports generated CSS Modules, global Sass/CSS entrypoints, and
React-compatible inline style maps. The build system uses the Dart `sass`
package, so compiling project styles does not require a global Sass install.

For conditional classes, inline style helpers, and fluent props builders, see
[Component authoring ergonomics](./component-ergonomics).

## CSS Modules

CSS Modules provide scoped, collision-free class names. Any configured file
ending in `.module.css`, `.module.scss`, or `.module.sass` is treated as a
module.

Create a stylesheet:

```scss title="lib/card.module.scss"
.card {
  padding: 16px;
  border-radius: 8px;
  background-color: #f9f9f9;
  box-shadow: 0 4px 6px rgb(0 0 0 / 10%);
}

.title {
  font-size: 1.5rem;
  font-weight: bold;
}
```

During a build, `react_tool` creates a typed Dart companion such as
`card.module.dart`. Import it from the component:

```dart title="lib/card.dart"
import 'package:react_dom/react_dom.dart';

import 'card.module.dart';

@reactComponent
ReactNode Card(({String title, ReactNode children}) props) {
  return div(
    className: CardModuleStyles.card,
    children: [
      h2(className: CardModuleStyles.title, children: [props.title]),
      props.children,
    ],
  );
}
```

The emitted class includes a stable scope suffix, so it cannot collide with a
class in another module. Treat `*.module.dart` as generated output and do not
edit it directly.

## Global styles

Declare application-wide entrypoints in `react.yaml`:

```yaml title="react.yaml"
styles:
  entrypoints:
    - web/global.scss
    - web/typography.css
  output: styles.css
```

The CLI compiles each entrypoint into `build/react/` and wires its stylesheet
link into generated browser and SSR entrypoints. When one entrypoint is
configured, `output` controls its emitted path.

## Inline styles

For state-dependent values such as progress or drag coordinates, pass the
`CssStyle` map returned by `css`. React expects a property map—not a serialized
CSS declaration string.

```dart
@reactComponent
ReactNode ProgressBar(({double percentage}) props) {
  return div(
    style: css(width: '100%', backgroundColor: '#eee'),
    children: [
      div(
        style: css(
          width: '${props.percentage * 100}%',
          height: 20,
          backgroundColor: 'blue',
          additionalProperties: {
            'transition': 'width 0.3s ease',
          },
        ),
      ),
    ],
  );
}
```

Use camel-case React property names. Numbers and strings are both accepted
because React interprets each property according to its own rules.

## CSS custom properties

Use `CssStyle.custom` to pass CSS variables from Dart state into a stylesheet:

```dart
@reactComponent
ReactNode ThemedBox(({String themeColor}) props) {
  final style = css()..custom('--box-theme-color', props.themeColor);

  return div(
    className: BoxModuleStyles.container,
    style: style,
    children: ['Hello World'],
  );
}
```

The same escape hatch works for new CSS properties that are not yet named
parameters on `css`:

```dart
final style = css(textAlign: 'center')
  ..custom('textWrap', 'balance');
```

Prefer classes and CSS Modules for stable presentation. Use inline styles for
values that genuinely depend on component state or props.
