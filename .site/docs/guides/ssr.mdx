# Server-side rendering

React Dart SSR uses a generated Node worker for React rendering and a Dart HTTP
server for routing, authentication, assets, and server functions.

```text
request
  -> Dart server adapter
  -> ReactSsrClient
  -> Node worker + ReactDOMServer
  -> HTML and serialized props
  -> index template
  -> browser hydrate
```

## Configure entrypoints

```yaml
client:
  entrypoint: web/client.dart
ssr:
  entrypoint: lib/ssr.dart
server:
  entrypoint: bin/server.dart
output: build/react
```

`react build` compiles the Dart client and SSR entrypoints, creates the Node
runtime, and records their paths in `bundle_manifest.json`.

## SSR entrypoint

The generated starter registers the same component IDs used by the browser:

```dart
import 'package:react_server/react_server.dart';

import '.generated/app.react.dart';
import '.generated/react_components.g.dart';
import '.generated/ssr_registry.g.dart';

void main() {
  registerReactComponents();
  SsrComponentRegistry.register(
    idApp.value,
    (props) => App(title: props['title'] as String? ?? 'React Dart'),
  );
  registerGlobalRenderer((id, props) => SsrComponentRegistry.build(id, props));
}
```

The worker executes a real React render stack, so hooks, contexts, suspense,
foreign components, memoization, refs, and error boundaries use the same
component contracts as the browser.

## Server adapter

The Dart server creates `ReactSsrClient` from `REACT_SSR_URL` and passes it
to either `RoutedReactApplication` or Shelf's `ReactServerApp`. The adapter
selects page props, asks the worker to render the root component, and replaces
`{{SSR}}` and `{{PROPS}}` in the index template.

When no worker is configured, the adapters fall back to static/client-only
serving.

## Hydration

```dart
import 'package:my_app/.generated/app.react.dart';
import 'package:my_app/.generated/react_components.g.dart';
import 'package:react_dom/react_dom.dart';

void main() {
  initReact();
  registerReactComponents();

  final root = getRoot('app');
  final props = getInitialProps();
  final app = App(title: props['title'] as String? ?? 'React Dart');

  if (hasSSRContent(root)) {
    hydrate(root, app);
  } else {
    mount(root, app);
  }
}
```

The browser's first node tree and props must match the server output. Avoid
request-time randomness, differing date formatting, or environment-dependent
branches during the initial render.

## Browser APIs

Portable Web types can appear in shared component signatures, but browser
globals are unavailable during SSR. Read browser state in effects or isolate a
subtree behind a client-only boundary. `react_analysis` detects direct browser
and JS-interop leakage into server contexts.

`useLayoutEffect` is a browser layout API; prefer `useEffect` unless the
component genuinely needs synchronous post-layout work.

## Test

Use `InMemorySsrHarness` for template substitution, `SsrTestHarness` for
worker protocol behavior, and `ReactTestHarness` with the application's real
`server_testing` adapter for compiled SSR, assets, deep links, and server
actions. Harness-allocated ports prevent accidental reuse of unrelated local
processes.
