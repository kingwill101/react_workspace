# SSR features and gaps

React Dart now supports buffered and streaming SSR, page metadata, explicit
document caching, and typed server-action state. The HTTP server adapter still
owns ordinary API routes and middleware.

## Supported today

- `@serverFunction` actions with codecs, contract hashes, and request context;
- `renderToString` and opt-in `renderToPipeableStream` through the Node worker;
- `react_tool prerender` for explicit routes or JSON route manifests;
- `ReactPartialDocument` for independently cached shells and dynamic regions;
- deep-link SSR with `react_router` server bindings;
- `ReactPageMetadata` for title, SEO, Open Graph, links, and JSON-LD;
- `ReactDocumentCache` with TTL, bounds, tag invalidation, and stale-while-revalidate;
- `ReactDocumentStore` for persistent or distributed document storage;
- `ReactRouteManifest` for route-specific ISR policies;
- `ReactDataCache.getOrLoad<T>` for deduplicated typed data loading;
- `useServerAction`, `serverActionSubmit`, and the React 19 optimistic-action helper;
- structured field-error extraction from action failures;
- `ReactAfterResponse` for scheduled server-function post-response work;
- Routed and Shelf API handlers mounted alongside the React fallback.

## Remaining work

- automatic route discovery for the existing `react_tool prerender` workflow;
- generated schema-aware form validation and field decoder helpers.

The explicit Dart cache API should remain the foundation rather than
introducing a source-transformed `use cache` directive prematurely.
