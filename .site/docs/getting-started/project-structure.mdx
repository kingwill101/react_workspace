# Project Structure

Understanding the layout of a React Dart project is crucial. Unlike standard Flutter or AngularDart projects, React Dart utilizes specific entrypoints for the client, the SSR worker, and the backend server. The `react_tool` CLI expects a certain layout, which is highly configurable via `react.yaml`.

Here is a typical directory structure for a React Dart application:

```text
my_react_app/
├── bin/
│   └── server.dart         # Backend server entrypoint
├── lib/
│   ├── components/         # Dart React components
│   │   ├── button.dart
│   │   └── header.dart
│   ├── server/             # Server functions and API logic
│   │   └── actions.dart
│   ├── app.dart            # Root component
│   └── ssr.dart            # Server-Side Rendering entrypoint
├── web/
│   ├── client.dart         # Browser hydration entrypoint
│   ├── index.html          # Base HTML template
│   └── styles.scss         # Global styles
├── react.yaml              # React Dart build configuration
├── pubspec.yaml            # Dart package configuration
└── build/                  # Generated by `react build` (ignored in git)
```

## Key Directories and Files

### `react.yaml`
This is the heart of your project configuration. It tells `react_tool` where your entrypoints are located, how to handle styles, and how to bundle foreign JavaScript dependencies.

```yaml
# react.yaml
client: web/client.dart
ssr: lib/ssr.dart
server: bin/server.dart

static: web
output: build/react

styles:
  entrypoints:
    - web/styles.scss
  output: styles.css
```

### `web/client.dart`
This file is compiled to JavaScript and runs in the browser. Its primary responsibility is to hydrate the HTML sent by the server. It uses `package:react_dom` to attach the React tree to the DOM.

```dart
import 'package:react_dom/react_dom.dart';
import 'package:my_app/app.dart';

void main() {
  hydrateRoot(
    document.getElementById('root')!,
    App(),
  );
}
```

### `lib/ssr.dart`
This file is compiled into a JavaScript worker (`ssr_runtime.mjs`). The Dart backend server invokes this worker to render components to HTML strings on the fly. It typically registers your server functions and exports a rendering function.

### `bin/server.dart`
This is a pure Dart executable. It starts an HTTP server (e.g., using `shelf`), serves static files from `build/react/`, routes SSR requests to the SSR worker, and handles incoming server function RPC calls.

### `web/index.html`
Your base HTML shell. The `react_tool` build process will inject necessary import maps and script tags into this file automatically, so you usually just provide the raw structure and a `<div id="root"></div>`.

### Generated Code (`.react.dart` and `.react.g.dart`)
When you run `react build` or `react serve`, the code generator creates sibling files for your components. For example, `button.dart` will generate `button.react.dart`. **Do not edit these files manually.** They contain the highly optimized factory functions and JavaScript interop boundaries necessary to render your components within the React JS runtime.

## Customizing the Structure

You are not locked into this specific layout. If you prefer to place your styles in an `assets` folder, or your client entrypoint in `frontend/`, simply update your `react.yaml`:

```yaml
client: frontend/main.dart
static: public
styles:
  entrypoints:
    - assets/css/main.scss
```
