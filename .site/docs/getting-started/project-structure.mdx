# Project structure

A generated application keeps the files you edit separate from build and
code-generation machinery.

```text
my_react_app/
├── bin/
│   └── server.dart
├── lib/
│   ├── .generated/          # React-owned output; ignored
│   ├── app.dart             # root UI
│   ├── greeting.dart        # example server function
│   └── ssr.dart             # Node SSR entrypoint
├── test/
│   ├── app_test.dart
│   └── greeting_test.dart
├── web/
│   ├── client.dart          # browser hydration entrypoint
│   ├── index.html
│   └── styles.scss
├── react.yaml
├── package.json
└── pubspec.yaml
```

Most application work happens in `lib/app.dart` and feature files such as
`lib/greeting.dart`. The scaffold includes the small browser, SSR, and server
entrypoints so the app runs immediately, but they normally change only when
customizing infrastructure.

## Authored entrypoints

### `web/client.dart`

Registers generated browser bridges and hydrates the root component using
`package:react_dom`. It imports the App factory from
`package:my_app/.generated/app.react.dart`.

### `lib/ssr.dart`

Registers the same component identities for Node rendering and exposes the
render callback consumed by the generated SSR worker.

### `bin/server.dart`

Hosts static assets, SSR responses, and server-function dispatch. The selected
starter uses either `react_server_shelf` or `react_server_routed`; transport
dependencies do not leak into portable `react_server`.

## Configuration

`react.yaml` controls entrypoints and outputs:

```yaml
client:
  entrypoint: web/client.dart
ssr:
  entrypoint: lib/ssr.dart
server:
  entrypoint: bin/server.dart

static: web
output: build/react

styles:
  entrypoints:
    - web/styles.scss
  output: styles.css
```

The conventional paths are defaults, so only override fields that differ.

## Generated and built output

`react generate`, `react build`, and `react serve` synchronize Dart
factories and registries into `lib/.generated/`. This directory is ignored by
Git and hidden by the scaffold's VS Code settings.

`build/react/` contains compiled browser, SSR, CSS, static, manifest, and
foreign-module artifacts. It is also disposable.

Never edit either directory. Change annotated Dart source, `react.yaml`, a
wrapper descriptor, or a generator and rerun the CLI.

## Custom layouts

Entrypoints, static content, styles, and the output directory are configurable.
Generated Dart sources still use the package's `lib/.generated/` boundary so
package imports remain stable.
