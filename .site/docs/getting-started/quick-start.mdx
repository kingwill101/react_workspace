# Quick start

## Create an application

Choose a starter and fetch its dependencies:

```console
dart run react_tool:react init my_react_app --template routed-minimal
cd my_react_app
dart pub get
```

Use `--template ssr` for Shelf-backed SSR, `routed` for the expanded Routed
starter, or `client` for a browser-only app.

## Start development

```console
dart run react_tool:react serve --watch
```

The command generates hidden Dart sources, compiles styles and browser code,
builds the Node SSR worker when configured, and starts the selected Dart
server. The default application URL is `http://localhost:8080`.

## Edit the root component

Open `lib/app.dart`. Component source imports the portable DOM entrypoint; it
does not import its own generated factory.

```dart
import 'package:react_dom/react_dom.dart';

@reactComponent
ReactNode App(({String title}) props) {
  final (count, setCount) = useState(0);

  return main(
    className: classNames('app-shell'),
    style: css(maxWidth: 640, margin: '0 auto', padding: 32),
    children: [
      h1(key: 'heading', children: [props.title]),
      button(
        key: 'counter',
        type: 'button',
        onClick: (_) => setCount(count + 1),
        children: ['Clicked $count times'],
      ),
    ],
  );
}
```

Stable keys keep list rendering warning-free in both browser and SSR output.
The generated browser and SSR entrypoints already import the App factory from
`lib/.generated/`.

## Validate

Run narrow checks before a production build:

```console
dart analyze --fatal-infos
dart test
dart run react_tool:react build --release
```

Scaffold tests use `react_testing` and the chosen `server_testing` adapter, so
they allocate their own ports and exercise the built application without an
external browser script.

Production artifacts are written under `build/react/`. Deploy the Dart server
with that directory and a Node runtime when SSR is enabled.
