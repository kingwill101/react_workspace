# Installation

## Requirements

- Dart SDK `>=3.12.0 <4.0.0`.
- Node.js with npm for managed React dependencies, bundling, and the SSR worker.
- A Rust toolchain compatible with the version declared by
  `react_tool/native/Cargo.toml` when building the native TypeScript
  declaration extractor.

The CLI keeps npm dependencies under `.dart_tool/react/js/`; it does not
install React globally or modify an application's `package.json`.

## Current pre-publication installation

The React Dart packages are currently available from GitHub, not as released
pub.dev versions. External applications must use a Git dependency with an
explicit ref until the packages are published:

```console
dart pub global activate --source git \
  --git-ref master \
  --git-path packages/react_tool \
  https://github.com/kingwill101/react_workspace.git
```

Application packages use the same repository/ref and the package path inside
the repository:

```yaml
dependencies:
  react:
    git:
      url: https://github.com/kingwill101/react_workspace.git
      ref: master
      path: packages/react
  react_dom:
    git:
      url: https://github.com/kingwill101/react_workspace.git
      ref: master
      path: packages/react_dom
```

Repeat this shape for every React Dart package the application imports, using
one ref consistently. Prefer an immutable commit ref for reproducible builds;
`master` is the active development ref.

Routed applications additionally use `routed_core`, `routed_io`, and
`routed_testing` from the same ref in
[`routed`](https://github.com/kingwill101/routed):

```yaml
dependencies:
  routed_core:
    git:
      url: https://github.com/kingwill101/routed.git
      ref: master
      path: packages/routed_core
  routed_io:
    git:
      url: https://github.com/kingwill101/routed.git
      ref: master
      path: packages/routed_io
```

The `routed_testing` adapter uses the same Git URL/ref with the path
`packages/server_testing/routed_testing`.

## Install the CLI

Once the package is published, the hosted installation becomes:

```console
dart pub global activate react_tool
react doctor
```

Within this GitHub workspace, use the workspace-resolved executable:

```console
dart pub get
dart run react_tool:react doctor
```

Run project commands from the directory containing that project's
`pubspec.yaml`.

## IDE setup

Generated application source lives under `lib/.generated/`; build artifacts
live under `build/`. Scaffolded projects include VS Code settings that hide
both:

```json
{
  "files.exclude": {
    "**/.dart_tool": true,
    "**/.generated": true,
    "**/build": true
  }
}
```

These directories are disposable. Navigation and edits should stay in authored
files such as `lib/app.dart`, feature files, and tests.

## Verify a project

```console
dart run react_tool:react init sample_app --template client
cd sample_app
dart pub get
dart run react_tool:react doctor
dart analyze --fatal-infos
dart test
dart run react_tool:react build
```

For SSR, use the `ssr`, `routed`, or `routed-minimal` template and keep
Node available when serving the generated worker.
